Suggested FastAPI connection

Connect the Run button to your workflow orchestrator. Suggested request payload:

POST /workflows/credit-risk/run
{
  "dataset": "synthetic | lendingclub | custom",
  "target": "loan_status",
  "champion": "logistic_regression",
  "challenger": "hist_gradient_boosting",
  "oot_pct": 20,
  "seed": 42,
  "stages": ["data_intake", "feature_engineering", "train_champion",
             "train_challenger", "validate", "governance", "api_tests", "monitor_deploy"],
  "agents": ["data_quality", "target_leakage", "feature_engineering",
             "modeling", "challenger", "validation", "model_risk_review",
             "explainability", "governance", "api_engineer", "qa_test",
             "monitoring", "devops", "report_handoff"]
}

Response: { "run_id": "uuid", "status": "queued", "events_url": "/runs/{run_id}/events", "artifacts_url": "/runs/{run_id}/artifacts" }

Production considerations: queue long-running jobs (Celery/RQ/Arq), persist run state, stream events via SSE/WebSocket, validate all request fields, use authentication/authorization, and keep dataset paths server-side allowlisted.
